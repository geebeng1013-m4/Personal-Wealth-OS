3. 代码质量分析

3.1 优点

  • 严格 TypeScript：tsconfig.json 启用 strict: true，目标 ES2022，代码中几乎无 any 使用（仅 unknown + 类型收窄）。
  • 纯函数设计：rules.ts 中所有计算函数均为纯函数，接受 WealthState 并返回结果，无副作用，易于测试。
  • 状态不可变：setState() 使用不可变语义，通过结构化克隆避免引用污染。
  • 数据安全：账本交易验证函数 validLedgerTransactions() 对每条记录进行严格校验（金额、日期、类型、账户引用）。
  • 防御性编程：市场数据模块对 Yahoo Finance API 返回结构做多层空值检查，缓存失效机制清晰。

3.2 发现的问题

问题 #1：ui.ts 过大（2,752 行）
单文件包含 11 个功能页面的全部模板生成和事件绑定逻辑，违反单一职责原则。新增或修改任何页面时需要在巨大文件中定位，维护成本高且容易引入回归。
问题 #2：硬编码汇率
market.ts 中 calcPnLForTicker() 默认汇率为 usdToMyr = 4.25，buildTradeTimelineHtml() 也硬编码 4.25。汇率应从用户配置或动态 API 获取。
问题 #3：缺少单元测试
项目完全没有自动化测试。rules.ts 中的成本基础计算（FIFO 卖出）、state.ts 中的迁移逻辑和 market.ts 中的风险指标计算均无测试覆盖。对于金融计算类应用，这是一个显著的风险。
问题 #4：CORS 代理依赖脆弱
market.ts 依赖 3 个公共 CORS 代理（allorigins、corsproxy、codetabs），这些第三方服务随时可能不可用或限流。建议部署自建代理或改用后端 API 路由。
问题 #5：HTML 模板字符串中的 XSS 风险
虽然大部分用户输入经过 escapeHtml() 处理，但 ui.ts 中有大量 innerHTML 赋值，且部分模板函数直接拼接来自 API 的数据（如 market.ts 的 buildTradeTimelineHtml() 中的 shortName、ticker），存在潜在 XSS 风险。
问题 #6：saveState 静默忽略无 UID 的保存
state.ts 中 saveState() 在 !uid 时直接 return，不做任何提示。如果调用方忘记传入 UID，用户的数据将不会被持久化，且无任何错误反馈。
问题 #7：Beta 计算前提假设不安全
calcRiskMetrics() 中计算 Beta 时假设 benchmarkPrices.length === prices.length，如果不相等则默认 beta = 1。实际场景中两个时间序列长度经常不一致，应做日期对齐。

5. 用户体验 (UX) 分析

5.1 优点

  • 信息架构清晰：页面按 Today / Plan / Grow / Reflect / System 五个分组组织，符合用户心智模型。
  • 深色/浅色主题：支持一键切换，使用 CSS 变量实现，对比度合理。
  • PWA 安装体验：Android 和 iOS 均有安装引导，iOS 提供分步图文指引。
  • 快照系统：每次重大操作前自动保存快照（最多 20 个），用户可随时回滚，降低了操作风险。
  • Quick View：提供 /quick 路径的快速查看模式，适合 PWA 快速启动。
  • 隐私遮罩：maskAmounts 功能一键隐藏所有金额，适合公共场合使用。

5.2 需改进的体验问题

UX 问题 #1：市场数据加载无骨架屏
行情数据通过 CORS 代理获取，可能需要 5-15 秒。在等待期间用户看不到任何加载指示器（取决于 UI 实现），容易误以为应用无响应。
UX 问题 #2：错误状态不一致
市场数据获取失败时（网络超时、代理不可用、API 返回异常），用户可能只看到空白区域而无明确的错误提示和重试按钮。
UX 问题 #3：移动端表单体验
财务输入表单使用 ，在 iOS 上会弹出数字键盘但失去小数点便捷输入；建议使用 inputmode="decimal"。
UX 问题 #4：首次用户引导缺失
新用户登录后直接看到默认状态数据（MYR 880 allowance 等），没有引导流程帮助理解各模块功能或进行初始配置。

6. 可改进模块与建议

[高优先级] #1 — 拆分 ui.ts

建议：将 ui.ts 按页面拆分为独立模块：
ui/dashboard.ts、ui/portfolio.ts、ui/ledger.ts、ui/market.ts、ui/settings.ts、ui/goals.ts、ui/buckets.ts、ui/advisor.ts、ui/rules.ts、ui/review.ts、ui/calculator.ts
保留 ui.ts 作为入口，负责导航、侧边栏和 renderApp() 调度。每个子模块导出自己的 render() 和 bind() 函数。

[高优先级] #2 — 添加金融计算单元测试

建议：使用 Vitest 为以下核心函数编写测试：
  • calculatePositionCostBasis() — FIFO 卖出、部分卖出、零持仓边界
  • migrateState() — 版本 3→14 的所有迁移路径
  • calcRiskMetrics() — 空序列、单点、正常数据、Beta 对齐
  • portfolioSummary() — 空持仓、单 ticker、多 ticker 配置

[高优先级] #3 — 动态汇率替换硬编码

建议：将 USD/MYR 汇率存入 WealthState.profile，默认从用户交易的 exchangeRate 字段取最新值，或通过 API 获取实时汇率。避免所有 4.25 硬编码。

[中优先级] #4 — 自建 CORS 代理或后端 API

建议：项目已有 Vercel API 路由（api/ 目录），可将行情请求移到后端 serverless function，消除对公共 CORS 代理的依赖。这也便于添加 API 缓存层（如 Vercel KV 或 Redis）。

[中优先级] #5 — 增强加载和错误状态 UI

建议：
  • 为所有异步数据加载区域添加骨架屏（skeleton loader）
  • 网络请求失败时显示可操作的错误消息 + 重试按钮
  • 缓存过期数据仍可展示，但需标注"数据时间"和"离线/陈旧"状态

[中优先级] #6 — XSS 防护加固

建议：
  • 审计 ui.ts 和 market.ts 中所有 innerHTML 赋值点
  • 对来自 API 的数据（shortName、symbol、marketState）统一经过 escapeHtml()
  • 考虑使用 textContent 替代 innerHTML 作为默认策略

[低优先级] #7 — 首次用户引导流程

建议：新增用户首次登录后显示简短的欢迎引导（3-5 步），帮助理解：Dashboard 概览 → Money Plan 分桶 → Investments 记录首笔交易 → Coach 查看建议。

[低优先级] #8 — Beta 日期对齐优化

建议：在 calcRiskMetrics() 中按日期对齐两个时间序列（取交集日期），避免因交易日不同导致长度不一致时 Beta 默认为 1 的问题。
